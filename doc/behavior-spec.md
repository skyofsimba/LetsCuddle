# 当前行为规格与验收清单

> **文档定位**：本文描述**当前 1.20.1 Forge 版本**对玩家可见的行为，是"需求说明"的实际形态，也是发版前的回归脚本。
>
> - 本文与 [`original-design.md`](original-design.md)（1.21 原版）**有意不同**的地方集中在 §5，别拿原版文档当验收依据；
> - 代码结构见 [`architecture.md`](architecture.md)，开发环境见 [`developing.md`](developing.md)。
>
> 改行为（消息文案、数值、判定顺序、交互方式）必须同步更新本文与 `CHANGELOG.md`。

---

## 1. 术语

| 术语 | 含义 |
|---|---|
| 券 | 物品 `letscuddle:hug_ticket`「抱抱券」 |
| 发起者 / 接受者 | 右键对方的人 / 被请求的人 |
| 请求 | 内存里的一条 `HugRequest`，60 秒过期 |
| 拥抱 | 一条 `HugStatus`，锁定 120 tick（6 秒） |
| 动作 | 普通拥抱（`normal`）/ 摸头拥抱（`touch_head`） |

---

## 2. 获得券

| 场景 | 行为 |
|---|---|
| 创造模式 | 「工具与实用物品」分类里有抱抱券；鼠标悬停显示两行：灰色说明 + 当前动作与切换方式 |
| 生存合成 | 3×3 十字：四角 `纸`、上下 `淡蓝染料`、中间 `粉色染料` → 4 张；配方类型 `crafting_shaped`，分类 `misc` |
| 每个存档首次进入 | 服务端判定 `world/playerdata/<uuid>.dat` 不存在 → 发 16 张（背包满则掉落）。语义是**该存档首次登录**，不是账号首次 |
| 堆叠 | 64 |

---

## 3. 发起请求

**触发**：手持券，右键另一名玩家（不按 Shift）。

| 步骤 | 结果 |
|---|---|
| 1 | 服务端检查：这对玩家已有未处理请求 → 只给发起者「你已经向他发送了一个拥抱请求」，**不扣券**，结束 |
| 2 | 否则登记请求（60 秒后过期，动作取券上 NBT 的当前选择，缺省「普通拥抱」） |
| 3 | 接受者收到：`<发起者> 向你发起了「<动作名>」拥抱请求! ` + 绿色 `[同意] ` + 红色 `[拒绝] `（按钮执行命令） |
| 4 | 发起者收到绿字：`你成功向 <接受者> 发送了「<动作名>」拥抱请求` |
| 5 | 扣 1 张券（无论后续同意/拒绝/过期，都不退还） |

**右键非玩家**（生物、方块、空气）：不发起请求，返回空操作（客户端会有挥手动画）。

**Shift + 右键**：不发起请求，改为切换动作（见 §4）。

---

## 4. 选择动作（v1.5）

| 项 | 行为 |
|---|---|
| 存储 | 券的物品 NBT，键 `Animation`，值 `normal` 或 `touch_head`；缺省 `normal` |
| 切换 | `Shift + 右键`（空中或玩家身上都行）循环切到下一个动作，**只在服务端改 NBT**（自动同步给客户端） |
| 反馈 | action bar：`当前动作：<动作名>`；tooltip 第二行同步更新 |
| 范围 | NBT 是**每张券**独立的；创造模式中键复制出的券会回到默认「普通拥抱」（原版行为，已知限制） |

---

## 5. 接受 / 拒绝

### 5.1 接受（判定顺序即行为，不可调换）

| # | 条件 | 不满足时 |
|---|---|---|
| 1 | 请求存在，且请求的接受者就是执行命令的人 | 接受者：`无效的拥抱请求` |
| 2 | 这对玩家当前不在拥抱中 | 双方：`<对方> 正在拥抱中,无法接受你的请求` / `你正在拥抱中,无法接受 <对方> 的请求` |
| 3 | 两人在同一维度 | 接受者：`你与 <发起者> 不在同一个世界` |
| 4 | `distance <= 5.0` | 接受者：`你距离 <发起者> 太远了! [>5]` |
| 5 | 落点可站立（脚下有碰撞、身体内无碰撞） | 接受者：`<发起者>前的区域无法站立!`（**不会**先收到「已接受」） |
| 6 | —— | 双方：`<接受者> 接受了你的拥抱请求!` / `你接受了来自 <发起者> 的拥抱请求!` |
| 7 | 接受者瞬移到落点 | 接受者被摆到「发起者另一侧」1.3 格，**双方**都转向对方眼睛 |
| 8 | 广播开始包 | 同维度、距发起者 < 64 格的玩家（含两名当事人）收到同一个动作 id |

### 5.2 拒绝

请求存在且执行者就是接受者 → 双方各收到红字：
`<接受者> 拒绝了你的拥抱请求.` / `你拒绝了来自 <发起者> 的拥抱请求.`，删除请求。
其他情况 → 接受者：`无效的拥抱请求`。

### 5.3 60 秒过期

到点后双方各收到：`关于 <对方> 的拥抱请求已经过期`（任何一方不在线则不打扰，仍删除请求）。券不退。

---

## 6. 拥抱过程

| 项 | 行为 |
|---|---|
| 时长 | 120 tick（6 秒） |
| 锁定 | 每 tick 把两人 `teleportTo` 回接受瞬间的位置；能转头、聊天、开背包，不能位移 |
| 广播范围 | 同维度、距发起者 < 64 格（含当事人）；正好 64 格不可见 |
| 动作 | 由**发起者**在券上选的那个动作；两台客户端播同一对互补动作 |
| 第三人称 | 当事人自动切第三人称；**相机以渲染出来的拥抱模型为中心**（v1.5.1） |
| F5 | 拥抱期间自己按 F5 换视角：结束后**不**强制还原，尊重玩家选择 |
| 提前结束 | 任一当事人按住潜行 5 tick（0.25 秒）→ 立即结束，动作立刻收掉，双方收到 `拥抱已结束` |
| 正常结束 | 120 tick 到点 → 广播结束，动作自然播完（略慢于锁定，约 6.1 秒） |
| 掉线 | 任一方掉线 → 立刻清理并广播结束（`cancelled`），另一方与旁观者都解锁、动作收掉 |
| 阴影 | 拥抱期间双方的影子被隐藏（模型有约 1 格位移，原版影子不会跟随） |

**结束时**：渲染锁解除，恢复原版渲染（护甲、手持物、披风回来）；相机回原位（若玩家没手动改过）。

## 7. 数值表

| 常量 | 值 | 位置 |
|---|---|---|
| 请求过期 | 60 秒（1200 tick） | `HugCommandHandler.REQUEST_TIMEOUT_TICKS` |
| 拥抱锁定 | 120 tick | `ANIM_TICKS` |
| 蹲下取消 | 5 tick | `SNEAK_CANCEL_TICKS` |
| 接受距离上限 | 5.0 格 | `MAX_DISTANCE` |
| 广播半径 | < 64 格 | `NEARBY_RADIUS` |
| 站位间距 | 1.3 格 | `STAND_OFFSET` |
| 站位盒半宽 | 0.3 | `STAND_HALF_WIDTH` |
| 脚下检测 | y−0.1 … y 需有碰撞 | `canStand` |
| 身体检测 | y+0.1 … y+1.7 需无碰撞 | `canPass` |
| 客户端锁兜底 | 200 tick | `RenderPlayerEventHandler.LOCK_TIMEOUT_TICKS` |
| 动作层 | `letscuddle:animations`，优先级 42，速度 ×0.5 | `AnimationManager` |
| 协议版本 | `3` | `HugNetwork.PROTOCOL` |
| 首登赠券 | 16 张 | `Letscuddle.onPlayerLoggedIn` |

## 8. 动作数据的契约（不要动这 4 份 JSON）

`assets/letscuddle/player_animation/{normal_s,normal_r,touch_s,touch_r}.json` 必须保持：

1. `"name"` 字段 = 注册 id（`hug_normal_sender` 等 4 个），**不是文件名**；
2. **不要加 `"version"` 字段**：缺省（=1）时解析器把 `torso` 当作整模根节点 `body`，这是「压进怀里」的实现基础；加 `"version": 3` 贴合会消失；
3. `"degrees": false` 保留（旋转是弧度）；
4. `stopTick=61`、`returnTick=2` 不改（与 120 tick 锁定对齐）。

## 9. 与原版（NeoForge 1.21 / HugMe v1.3）的有意差异

| # | 项 | 原版 | 当前 | 原因 |
|---|---|---|---|---|
| D1 | 命名空间 / 物品 id | `hugme:*` | `letscuddle:*` | 移植后换了模组身份 |
| D2 | 命令 | `/hugme acceptRequest` | `/letscuddle acceptRequest` | 同上 |
| D3 | 动作选择 | 服务端随机 | **发起者在券上选** | 需求 |
| D4 | 第三人称 | 不切 | 当事人自动切，且镜头以模型为中心 | 需求 + v1.5.1 修复 |
| D5 | 早退 | 只能等 6 秒 | 潜行 0.25 秒可取消 | 需求 |
| D6 | 阴影 | 留在原地（错位） | 拥抱期间隐藏 | 需求（无法跟随，见 architecture §6.4） |
| D7 | 协议 | v1（4 字段、int 序号） | v3（5 字段、字符串 id） | 支持取消与稳定 id |
| D8 | 请求过期 | 调度线程池 | 服务端 tick 计时 | K1/K2 修复 |
| D9 | 「已接受」消息顺序 | 校验之前 | 校验之后 | K3 修复 |
| D10 | 掉线解锁 | 不广播（旁观者卡住） | 广播结束 + 客户端 200 tick 兜底 | K9 修复 |
| D11 | 动作缺失 | NPE | 只警告不播 | K19 修复 |

**原样保留**（有意，不是漏改）：落点在发起者另一侧（K4）、模型高度（K7）、有序请求键（K12）、
失败仍 `sidedSuccess`（K16）、状态不持久化（K17）、首登 `.dat` 判定（K20）。

## 10. 验收清单

每项都在「两名玩家 + 一个旁观者」的环境下验证；建议先 `F5` 切到第三人称观察。
勾选方式：发版前把本表复制到 issue/PR 里逐条打勾。

### A. 基础行为（对应当年 C1–C17）

| # | 检查项 | 期望 |
|---|---|---|
| A1 | 首次进入新存档 | 背包 16 张；退出重进不再发 |
| A2 | 创造物品栏 | 「工具与实用物品」有抱抱券，tooltip 两行 |
| A3 | 合成 | 十字摆法（四角纸 / 上下淡蓝 / 中间粉）出 4 张 |
| A4 | 右键另一玩家 | 发起者扣 1 张 + 绿字；接受者收到带 `[同意][拒绝]` 的消息，按钮可点 |
| A5 | 重复右键同一人 | 只收到「你已经向他发送了一个拥抱请求」，券不扣 |
| A6 | 同意后站位 | 两人相距 1.3 格、面对面；**接受者模型压进对方怀里约 1 格**（东西南北各测一次） |
| A7 | 拥抱中锁定 | 两人无法位移，仍能转头/聊天；持续约 6 秒；64 格内旁观者可见，64 格外不可见 |

| A10 | 异维度 | 只有接受者收到「不在同一个世界」 |
| A11 | 落点被堵 | 只有接受者收到「无法站立」，**且不会先收到「已接受」**（K3 已修） |
| A12 | 60 秒不处理 | 双方各收过期提示，券不退 |
| A13 | 拒绝 | 双方各收拒绝提示，无动作 |
| A14 | 两种动作都能播 | 用 §4 的方法切到「摸头拥抱」再发起，动作不同（不再随机） |
| A15 | 第一人称 | 拥抱中按 F5 到第一人称：能看到自己身体处于拥抱姿势 |
| A16 | 拥抱中一方退出 | 另一方立刻解锁并恢复原版渲染（K9 已修） |
| A17 | 专用服务端不装 playerAnimator | 服务端能启动、能收请求、能瞬移，只是不播动作 |

## 11. 已知限制（当前版本接受）

- 无权限、无冷却、无无敌/摔落保护；拥抱中被第三方攻击仍会掉血（刻意保持原行为）；
- 用每 tick 传送实现锁定，会被传送拦截、反作弊、位移校正类模组打断；
- 状态只在内存里，服务端重启即清空；
- 创造模式中键复制券会丢动作 NBT；
- 首登发券在「首次进入后、存档保存前断线」的极端情况下会重复发；
- 阴影在拥抱期间被隐藏而不是跟随模型（技术原因见 `architecture.md` §6.4）。
