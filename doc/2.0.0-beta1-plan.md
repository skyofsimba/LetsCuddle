### 0.1 这个项目在做什么

一个 Minecraft 社交模组：玩家手持「贴贴券」右键另一名玩家发起请求，对方在聊天栏点「同意」后，两人被摆成面对面、播放一段互补的拥抱动画、锁定 6 秒；附近 64 格内的玩家都能看到。

- modid / 物品：`letscuddle` / `letscuddle:cuddle_ticket`
- 命令：`/letscuddle acceptRequest <sender>`、`/letscuddle rejectRequest <sender>`
- 当前发布线：Minecraft **1.20.1 / Forge 47.4.29**，版本 **1.6.0**
- 2.0 的目标平台：1.20.1 Forge + **1.21.11 Fabric**（1.21.1 NeoForge 明确不做）

### 0.2 2.0.0-beta1 只做两件事

1. **跨版本**：同一份源码产出 1.20.1 Forge 与 1.21.11 Fabric 两个 jar。
2. **动作包外置**：动作数据从"写死在 jar 里的四份 JSON + 枚举"变成"资源包里的 manifest + 数据驱动注册表"，支持 F3+T 热重载、能力协商、缺包回退。

### 1.4 1.x 已经踩过的坑（细节见归档）

1. **1.20.1 的 Access Transformer 必须写 SRG 名**：`Camera#setPosition` 写成 `m_90581_`，写官方名会静默不生效。
2. **不要删 MixinGradle**：本模组没有自己的 mixin，但 run 任务需要它给依赖模组的 mixin 注入 remap 参数。
3. **`Model#renderToBuffer` 1.20.1 是 8 参浮点颜色**，不是 1.21 的 int 颜色。
4. **动作 JSON 不要加 `version`**：`torso` 缺省被当作根节点 `body`；加了贴合消失。
5. **阴影**：1.20.1 的阴影按实体坐标单独画，接管渲染时要用 `setInvisible` + `AFTER_ENTITIES` 复位。
6. **K10**：`model.head.visible` 是共享模型实例，隐藏后要记录并在解锁时恢复。
7. **K19**：动作缺失时只警告，不要 `new KeyframeAnimationPlayer(null)`。

## 2. 目标与范围

### 2.1 平台矩阵

| 平台 | MC | 加载器 | 状态 | 说明 |
|---|---|---|---|---|
| `forge-1.20.1` | 1.20.1 | Forge 47.4.29 | **必须** | 现有玩家线；行为冻结，只加包功能 |
| `fabric-1.21.11` | 1.21.11 | Fabric Loader 0.19.3 + Fabric API | **必须** | 新线；最后一个混淆版本，工具链稳定 |

**不做的版本**：26.x（去混淆 + Java 25 + 渲染再改，是下一次大迁移）、**1.21.1 NeoForge**（2026-11-23 明确不做，P8 取消）、1.20.2–1.20.6、1.21.2–1.21.10、Quilt、Forge 1.21（不存在）。

### 2.2 两个目标

**G1 跨版本**：同一份 `common/` + 两个平台工程，产出两个可独立安装的 jar；1.20.1 的行为与 1.6.0 完全一致，1.21.11 达到功能对等（见 §8.3）。

**G2 动作包外置**：

- 动作由**资源包**提供（`assets/<ns>/cuddle_animations/*.json` + 引用的玩家动画）；
- 动作 id 全程字符串（协议、NBT/组件、命令、日志）；
- 注册表在客户端从所有资源包构建，**F3+T 热重载**；
- 服务端不解析包，通过**能力握手**知道每个客户端有哪些动作；
- 缺包/坏包/旧 id 都有确定性的回退；
- 同一动作 id 的**内容版本**（manifest `content_version`）在两端不一致时回退，避免"同 id 不同动作"；
- 内置动作作为 jar 内的最低优先级包，永远可用；
- 提供**给包作者的格式规范 + 制作指南 + 测试包模板**。

### 2.3 非目标（beta1 明确不做）

- 动作选择 GUI / 预览 / 图标（`icon` 字段保留但不生效）。
- 服务端主动分发资源包（`resource-pack=` 由服主自己配）。
- 音效、粒子、Molang、变量、动作混合/过渡。
- 新玩法（飞行贴贴、多人贴贴、持久化状态、权限/冷却）。
- 1.20.1 的渲染重构（例如"包一层保留盔甲"）——技术债，2.0.0 之后再说。
- 26.x / **1.21.1 NeoForge** / `hugme` 兼容构建。

## 3. 关键决策（ADR）

> 每条都写"为什么"，因为下一位 AI 很可能会想改回去。改之前先读"代价"。

### D1 平台矩阵：1.20.1 Forge + 1.21.11 Fabric（1.21.1 不做）

- **背景**：1.20.1 是现有玩家线；1.21.11 是最后一个混淆版本，Loom/Mojmap 在这一线稳定；26.x 起去混淆 + Java 25，生态要重来。
- **决定**：beta1 只做 1.20.1 Forge 与 1.21.11 Fabric 两个目标；1.21.1 NeoForge **明确不做**（2026-11-23，P8 取消），需要时另开版本。
- **代价**：两个平台两套胶水；1.21.11 与 1.20.1 的渲染架构完全不同，不能共用渲染代码。

### D2 不迁移 GeckoLib

- **背景**：GeckoLib 本身跨 Forge/Fabric/NeoForge 与多个 MC 版本（1.20.1 = 4.7.x，1.21.11 = 5.4.3），看起来是"跨版本答案"。
- **事实**：
  1. GeckoLib 动画的是它自己的 `GeoModel`/`GeoBone`，**不原生支持原版玩家模型**；官方文档只有 entity/block/item/armor 四类。
  2. 社区桥 **GeckoLib Player Compat** 目前只有 26.1.2 / `1.0-beta.1`，没有 1.20.1，也没有 1.21.11。
  3. GeckoLib 4（1.20.1）与 5（1.21.11）是**两套概念**（5.x 为 RenderState/instanced 重写），迁移等于做两次。
  4. 走"替换玩家模型"路线（Yes Steve Model 那种）会丢皮肤/盔甲/披风/手持物的兼容，工程量远超本模组。
- **决定**：不迁。动画库只作为"播放器"，数据格式不变。
- **代价**：没有 GeckoLib 的可视化生态；换来的是零美术重做、保留原版皮肤。

### D3 双动画后端，同一份数据

- **决定**：
  - 1.20.1：继续 playerAnimator `1.0.2-rc1+1.20`（现状，不动）。
  - 1.21.11：**PAL**（Player Animation Library，Zigy，playerAnimator 的官方继任者），它支持 1.21.11，且明确"能加载 PlayerAnimator 格式的全部动画"。
  - 两份后端实现同一个 3 方法约定（`play` / `stop` / `bodyOffset`），调用点一致；**不强行抽公共接口**（平台类型不同，`Object` 化只会更难读）。
- **理由**：四份动作 JSON 不用重做；PAL 的版本矩阵覆盖 1.21.1 / 1.21.11 / 26.x，是"新线"的长期答案。
- **代价**：两套库的 API/语义不同（PAL 的 body 位移在代码 API 里是像素、骨骼名 snake_case），必须用 **P7 的数值对比**确认文件加载后的实际位移；PAL 是较新的 fork，需锁版本。
- **退路**：如果 PAL 在"接管渲染"下取不到 body 位移，或位移语义不对，写一个 ~250–400 行的内部关键帧播放器（数据只有 6 根骨骼、单一缓动），1.20.1 作为 oracle 逐 tick 对比。见 §10 R2。

### D4 单仓双构建 + 纯 Java `common/`

- **决定**：
  - `forge-1.20.1/` 与 `fabric-1.21.11/` 各自是**独立 Gradle 构建**（各自的 wrapper、JDK、插件），不共用一个 `settings.gradle`。
  - `common/src/main/java/` 是**无构建文件的源目录**，两个平台用 `sourceSets.main.java.srcDir` 引入。
  - `common` 里禁止 `net.minecraft.*`（可以用 Gson，两个平台都有）。
- **理由**：FG6 要 Gradle 8.8 + JDK 17，Loom 1.17 要 Gradle 9.5 + JDK 21，硬合一个构建是自找麻烦；`common` 只放真正跨版本稳定的算法/常量/数据模型。
- **被否**：Architectury（抽象的是加载器，不是 MC 版本；1.20.1 与 1.21.11 仍需两套）；Stonecutter（可行，但预处理器会引入新的调试面；等目标 ≥3 或同步变痛再评估）。
- **代价**：平台胶水（物品/命令/网络/渲染/相机，约 700–800 行）要维护两份；用"同名类、同结构"降低 diff 成本。

### D5 动作 id 字符串化 + 数据驱动注册表

- **决定**：删除 `CuddleAnimationEnum`；所有入口（NBT/组件、协议、请求、日志）用 `String id`；注册表是 `Map<String, CuddleAnimDef>` 的不可变快照。
- **理由**：包是外部数据，枚举不可能穷举；1.5 已经把协议从 ordinal 改成字符串，这次只是把"两个常量"换成"注册表"。
- **代价**：所有 `CuddleAnimationEnum` 的调用点要改；旧 NBT 要迁移（`normal` → `letscuddle:normal`）。

### D6 动作包 = 资源包 `assets`；客户端注册表；服务端只做能力握手

- **决定**：
  - manifest 放 `assets/<ns>/cuddle_animations/<path>.json`；实际动画放库要求的 `player_animation(s)/`。
  - 客户端用 `SimpleJsonResourceReloadListener`（Forge）/ `ResourceManagerHelper`（Fabric）扫描并构建快照。
  - 服务端**不解析包**；客户端在加入/重载后上报 `id → lock_ticks`，服务端只用于校验与锁定。
- **理由**：服务端的资源管理器对"外部 resourcepacks 目录"的覆盖不可靠；而动作是纯客户端表现，服务端只需要知道"对方有没有"。
- **代价**：新增 C2S 能力包与超时逻辑；旁观者缺包时只能降级（不播动作）。

### D7 协议 v4

- **决定**：`PROTOCOL = 4`；新增 `Caps` / `Select` / `Selected` / `RequestCaps`，`Render` 保持字段（id 语义变为字符串 id）。
- **理由**：选择需要客户端→服务端；能力需要双向；旧协议没有这些。
- **代价**：1.6 与 2.0 不能互连；必须写迁移说明。

### D8 1.21.11 渲染：优先"包一层"，失败再"取消重画"

- **背景**：1.21.11 的玩家渲染是 `AvatarRenderer`（原 `PlayerRenderer`）+ `AvatarRenderState` + `SubmitNodeCollector`；Fabric 没有 Forge 的 `RenderPlayerEvent`。
- **决定**：
  - **1.20.1 完全不动**（继续取消重画）。
  - 1.21.11 先试 **`AvatarRenderer#setupRotations` 末尾**：`push` 后叠加 `Ry(targetYaw - bodyYaw)`，让原版渲染器继续画模型/皮肤/盔甲/手持物。
  - 如果该注入点不可用，退回 **取消 + 自绘**（用 `SubmitNodeCollector` 提交模型）。
- **理由**：包一层能白拿盔甲/手持物/皮肤层，代码量也小；自绘要重新处理模型提交、阴影、名字牌。
- **代价**：两种渲染实现的代码不共享；1.21.11 的阴影/名字牌行为要单独验证。

### D9 锁定时间由 manifest 声明，服务端取双方最小值

- **决定**：`lock_ticks` 默认 120，范围 20–400；客户端随能力上报；服务端在"接受"时取 `min(sender, receiver)`。
- **理由**：包可以比 6 秒长/短；固定 120 会把长动作硬切。
- **代价**：服务端信任客户端上报的值（夹紧 + 只影响社交动作，风险可接受）。

### D10 1.x 冻结 / 发布分支

- **决定**：2.0 开发在 `feat/2.0.0-beta1`；`main` 在 beta1 发布前保持 1.6 状态；发布后 `main` 前进到 2.0，另建 `release/1.x` 承接 1.x 热修。
- **理由**：1.20.1 玩家不能因为 2.0 开发而断更；1.x 的 tag `v1.6` 是稳定基线。

### D11 所有构建统一 `letscuddle` id

- **决定**：1.21.11 也用 `letscuddle`（物品 `letscuddle:cuddle_ticket`、动作 `letscuddle:*`）。
- **理由**：资源包、语言键、存档、文档只需要一套；`hugme` 是上游原版的品牌，不在本仓库产出。
- **代价**：不能直接拿本仓库的构建去替代上游 HugMe 的安装（那是另一个发布物）。

### 4.3 `common/` 的边界

**可以放**：
- 常量（§1.3）；
- 落点/站位数学（纯 `double` / 自定义 `Vec3d`）；
- 动作 id 的校验/规范化/排序；
- `CuddleAnimDef`、`CuddleCaps` 等纯数据 record；
- manifest 解析（Gson）与校验；
- 协议字段顺序的注释/常量（不含网络类）。

**不可以放**：
- 任何 `net.minecraft.*`（包括 `ResourceLocation`/`Identifier`/`Component`/`ItemStack`）；
- 平台事件、注册表、渲染、网络类；
- 需要资源管理器/世界/玩家对象才能做的事。

**包含方式**（两个平台各写一次）：
```groovy
sourceSets.main.java.srcDir '../common/src/main/java'
sourceSets.main.resources.srcDir '../common/src/main/resources'
```

**Java 级别**：`common` 必须能用 **Java 17** 编译（1.20.1 是 17）。不要用 Java 21 语法（switch 模式匹配、record pattern、virtual threads）。

**测试**：单元测试放在 `forge-1.20.1/src/test/java`（FG6 + JUnit 5），因为 1.20.1 是参考平台；`common` 的类会被编进 main，测试直接引用。

### 4.7 数据流

```
A 潜行+右键（客户端）
  → C2S Select(animId, hand)
  → 服务端校验 animId ∈ A 的 caps，写 NBT/组件
  → S2C Selected(animId)  → A 的 action bar 显示名字

A 右键 B（服务端 interactLivingEntity）
  → 读券上的 animId
  → 若 B 的 caps 没有它 → 回退 letscuddle:normal + 提示 A
  → 记录 request(animId, lockTicks)

B 点「同意」
  → 校验/落点/安全
  → lock = min(A.lock, B.lock)（夹紧）
  → 传送 B、双方 lookAt、广播 S2C Render(start, animId) 给 64 格内玩家
  → 客户端：注册表解析 animId → backend.play(sender, receiver, def)
  → 渲染接管：面对面 + body 变换

结束/蹲下/掉线
  → S2C Render(done, cancelled)
  → 解锁；cancelled=true 时立即 stop

F3+T
  → 资源重载线程重建注册表 → 原子替换
  → 客户端重发 C2S Caps
  → 服务端替换该玩家的能力快照
```

### 4.8 线程模型

- 服务端：所有状态（`REQUESTS`/`CUDDLES`/`CAPS`）只在服务端主线程读写；包处理用 `enqueueWork`/`context.server().execute` 回主线程。
- 客户端：网络处理回客户端主线程；注册表用 `volatile` 快照，重载线程只写新对象，不原地改。
- 禁止 `ScheduledExecutorService` / 自建线程（1.x 的 K1/K2 教训）。

## 5. 动作包（摘要，细节见规范）

- 一个包 = 资源包；manifest 在 `assets/<ns>/cuddle_animations/<path>.json`，id = `<ns>:<path>`。
- 部署：服务端只装 mod，**不装包**；发起者/接受者装 mod + 同一个包（同一个 `content_version`）；旁观者包可选。
- 客户端还需要动画库：1.20.1 是 playerAnimator（`mods.toml` `side="CLIENT"`），1.21.11 是 PAL（`suggests` + 守卫）；**服务端两版都不需要**。
- manifest 字段：`format`、`content_version`、`sender`、`receiver`、`name_key`、`name`、`speed`、`lock_ticks`、`order`、`icon`（保留）。
- 内置两个动作作为最低优先级包；`letscuddle:normal` 必须永远可用。
- 覆盖 = 同路径；新增 = 新路径；删除 = 移除包后 F3+T。
- 校验/上限/安全边界见 [规范](animation-pack-format.md) §2.3、§7。
- 包作者文档：[制作指南](animation-pack-authoring.md)（beta1 的交付物之一）。

## 6. 协议 v4

### 6.1 包清单

| # | 方向 | 名称 | 字段（按线上顺序） | 编码 | 上限/说明 |
|---|---|---|---|---|---|
| 0 | C2S | `CuddleCapsPayload` | `protocol:int`、`format:int`、`count:varint`、`(id:utf, lock:int, contentVersion:utf)` × count | `FriendlyByteBuf` / `StreamCodec` | 256 条；id ≤128；version ≤32；lock 20–400 |
| 1 | C2S | `CuddleSelectPayload` | `animId:utf`、`hand:byte`（0=主手，1=副手） | 同上 | id ≤128；每 tick 最多 1 次 |
| 2 | S2C | `CuddleRenderPayload` | `sender:utf`、`receiver:utf`、`done:bool`、`cancelled:bool`、`animId:utf`、`contentVersion:utf` | 同上 | 结束包两个字符串为空 |
| 3 | S2C | `CuddleSelectedPayload` | `animId:utf` | 同上 | action bar 用 |
| 4 | S2C | `CuddleRequestCapsPayload` | 无 | 空包 | 登录时服务端发 |

- Forge：`SimpleChannel` 的 message id 0–4，协议字符串 `"4"`；`NetworkRegistry.newSimpleChannel` 的版本断言直接拒绝 1.6 客户端。
- Fabric：`PayloadTypeRegistry.playC2S()/playS2C()` 注册；`fabric.mod.json` 不强制版本，靠 caps 里的 `protocol` 判断。

### 6.2 时序

1. 玩家 JOIN → 服务端发 `RequestCaps` → 客户端回 `Caps`。
2. 客户端 F3+T → 重建注册表 → 再发 `Caps`。
3. 客户端切换动作 → `Select` → 服务端写 NBT/组件 → `Selected`。
4. 发起/接受/广播/结束见 §4.7。
5. 玩家 DISCONNECT → 删除该 UUID 的 caps。

### 6.3 降级规则

| 情况 | 行为 |
|---|---|
| 服务端 100 tick 没收到 caps | 按"只有内置动作"处理；给该玩家一条提示（`anim_unavailable`） |
| caps 的 `protocol ≠ 4` | 记录并忽略该 caps；按内置处理（Forge 已在通道层拒绝） |
| 接受者没有发起者选的动作 | 回退 `letscuddle:normal`；给发起者一条提示 |
| 发起者自己也没有（包被删） | 静默回退默认 |
| 两端同 id 但 `content_version` 不同 | 回退默认；给发起者一条提示（`anim_version_mismatch`） |
| 旁观者没有该动作 / 版本不同 | **本地回退内置默认动作**（不僵住）；debug 日志一次 |
| `lock_ticks` 两端不同 | 取 min |
| 动作 id 非法/超长 | 服务端拒绝该 caps 条目；`Select` 忽略 |

### 6.4 安全

- 服务端只接受 caps 里的 id；正则在 common 里（§4.6 `CuddleIds`）。
- `count` 上限 256；`id` 长度上限 128；`content_version` 长度上限 32；lock 夹紧；`hand` 只接受 0/1。
- `Select` 频率限制：同一玩家每 tick 最多处理一次。
- 不因为包内容踢人；只有协议不匹配才拒绝连接（Forge 通道层）。

### 8.4 动作数值 oracle（1.20.1 → 1.21.11）

1. 在 1.20.1 上临时加日志：从 `IAnimatedPlayer#playerAnimator_getAnimation()` 每 tick 取 `head/body/leftArm/rightArm/leftLeg/rightLeg` 的 `POSITION`/`ROTATION`，写 CSV：
   `tick,bone,px,py,pz,rx,ry,rz`，tick 0–61。
2. 在 1.21.11 上用同法（PAL 的 controller/bone 或自己的采样器）导出同格式。
3. 对比：`|Δ| ≤ 1e-3`（弧度/米）；如果 PAL 的缓动/插值与 playerAnimator 有系统性差异，先确认是不是"同一 tick 语义"（速度 0.5、起始 tick 0）。
4. 通过标准：6 根骨骼 × 7 列 × 62 tick 全部在容差内；否则记录偏差最大的三个 tick，先修再继续。

> 这是本计划里**最重要的一条测试**：它把"AI 看不到动画"变成可判定的数值问题。
> 不要用"看起来差不多"替代它。

## 11. 已知坑（2.0 新增；1.x 的坑见归档）

### 11.1 1.21.11 / Fabric

1. **`ResourceLocation` → `Identifier`**；`PlayerRenderer` → `AvatarRenderer`；`PlayerRenderState` → `AvatarRenderState`；`Player` 之上多了 `Avatar` 父类。照抄 1.20.1 代码必炸。
2. **实体渲染是 render state + `SubmitNodeCollector`**（1.21.9 起）；`model.setupAnim(entity, ...)` 的旧写法不适用。
3. **Fabric 没有 `RenderPlayerEvent` / `ViewportEvent`**：必须 mixin；mixin 配置只放 client。
4. **`Item.Properties().setId(...)`**（1.21.2+）：漏了会 `Item id not set`。
5. **`ClickEvent` / `appendHoverText` / `use` 的签名在 1.20.5+ 变过**：以 mappings 为准。
6. **`teleportTo`**：`ServerPlayer` 要用带 `ServerLevel`/`Set<Relative>` 的重载；旧的三参 `teleportTo` 在 1.21.11 不一定存在。
7. **`isShiftKeyDown` / `lookAt` / `getPlayerByName`** 等逐个核实（名字可能没变，但别假设）。
8. **Loom 1.17.19 要求 Gradle 9.5.1**；不要升 Loom 1.18（要 JDK 25 跑 Gradle）。
9. **Yarn 在 1.21.11 之后停止**；本工程用 Mojmap，不要混 Yarn 名。
10. **PAL 的 mod id** 从它的 `fabric.mod.json` 读，不要猜；`depends` 写错会"依赖缺失"。
11. **PAL 的动画目录是 `player_animations/`（复数）**；playerAnimator 是单数。
12. **`SubmitNodeCollector` 的提交是延迟的**：模型姿势要在提交前定稿；不要在提交后改 `ModelPart`。
13. **名字牌/阴影**在 1.21.9+ 的绘制路径变了：先测，再决定用不用 1.x 的 `setInvisible` 技巧。
14. **Fabric 没有 per-side `depends`**：PAL 这类客户端库放 `suggests` + `isModLoaded` 守卫；写进 `depends` 会让专用服务端也必须装它。

### 11.2 构建

1. **两个 wrapper 不能混用**：FG6 用 Gradle 8.8，Loom 1.17 用 Gradle 9.5.1。
2. **JDK**：Forge 17、Fabric 21；CI 两个 job 分开。
3. **腾讯镜像**：本机 Forge wrapper 指向 `mirrors.cloud.tencent.com`；CI 不通就换官方 URL（§9.5）。
4. **`processResources` 的 `${}` 展开**：`mods.toml`/`fabric.mod.json` 里的占位符别写错；资源文件里不要出现会被 Groovy 当表达式的 `${...}`。
5. **`anim/raw` 必须从 jar 排除**，否则两个平台各多一份无用文件。
6. **`splitEnvironmentSourceSets`**：客户端类只在 `src/client/java`；服务端入口不要 import 客户端类。
7. **Fabric 首次构建**：Loom 下载 MC + 映射，10–30 分钟；不是卡死。

### 11.3 协议/数据

1. **协议 3 → 4**：旧客户端必须被拒绝（Forge 通道）或提示（Fabric）。
2. **旧 NBT**：`normal`/`touch_head` 迁移；不要直接丢弃。
3. **caps 超时**：100 tick 没有 caps 时用内置；不要无限等。
4. **包 id 正则**：服务端也要校验，不能只信客户端。
5. **lock_ticks 夹紧**：20–400；两端取 min。
